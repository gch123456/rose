# 持久化与后端讨论

日期：2026-11-11（北京时间）。用户确认离线游玩边界，其余为架构建议，不是已批准的实施设计。当前项目尚无存档或后端。

## 已知需求与当前事实

- 用户选择有限开局次数，用完通过广告或分享补充；分享路径仍需核对目标平台。
- 本轮用户明确：已有次数可离线开局，广告补次数需要联网。尚未确认离线自然恢复、跨设备玩家存档或账户体系。
- 玩家移动、自动攻击、怪物与伤害在客户端运行。单机游戏可以有存档/奖励后端，并不因此需要实时联机战斗服务器。
- `assets/scripts` 中未发现持久化或网络请求接口的现有调用，与 DESIGN 中未接存档/SDK 的状态一致。

## 建议保存的数据

| 数据 | 建议保存位置 | 说明 |
| --- | --- | --- |
| 音乐/音效音量、振动、画质、操作偏好 | 本地 | 修改后保存，通常无需账号同步 |
| 教学步骤、首次提示标记 | 本地，可随进度备份 | 避免重开应用后反复教学 |
| 通关记录、关卡/动物解锁、个人最好成绩 | 原型本地；正式版按需求云备份 | 仅保存最终确定的系统；不提前添加尚未确认的养成 |
| 次数余额、恢复计时基准、离线扣减事件 | 本地缓存与账本；联网后与服务端对账 | 不能只存一个余额或用最后登录时间重置恢复进度 |
| 广告奖励交易、发放状态与领取记录 | 正式版建议服务端，客户端保留待确认记录 | 校验平台结果，按交易唯一标识防重发 |
| 玩家身份与存档版本/修订号 | 本地＋需要时服务端 | 匿名身份如何恢复/绑定账号另定；本机生成 ID 本身不能保证换机找回 |
| 中途一局的恢复快照 | 本地，可选 | 若承诺杀进程后续局，需要关卡、时间、生命、装备、随机/敌人状态或明确恢复规则；仅进入后台暂停不等于持久化续局 |
| 货币、永久强化、皮肤、购买权益 | 相关功能确定后再保存 | 当前均不自动视为需求；涉及真实购买时另做交易验证与恢复设计 |

伤害数字、粒子、音效播放进度和每帧敌人坐标无需持续写数据库。普通游玩只在设置变化、关键进度、开局扣次和结算等事件落盘；续局快照另定频率与完整性。
怪物属性、武器数值、关卡配置属于版本化游戏配置，不应为每名玩家重复保存一套。
分析用的开局/结束、存活时长、失败原因、次数耗尽和广告完成事件与权威玩家存档分开；分析日志不用于直接发奖，采集范围与发行平台另定。

## 后端方案比较（建议，未选型）

1. **纯本地存档**：适合当前玩法原型，开发快、可离线；无法可靠约束改时间、改次数或伪造奖励，也不自动提供换机恢复。
2. **本地存档＋轻量后端**：建议用于带广告补次数的正式版。客户端负责战斗、离线存档与待同步记录，服务端负责身份、奖励验证/账本和对账，按需求备份长期进度。
3. **托管云服务**：可承载上述服务端职责，减少部分运维，但平台支持、验证回调、数据规则与费用仍需选型，不能只上传一个 JSON 就认为奖励可信。

建议先完成本地持久化与可玩体验，再在正式广告接入前选定后端。用户熟悉 Java，可考虑单体 Spring Boot＋MySQL；当前不创建服务、数据库或接口项目。此处是技术建议，不是用户已批准的选型。

## 已确认离线规则带来的边界

- 断网时读取缓存次数，开局扣 1 次并可靠保存唯一开局事件；断线后的同一局不因网络重试再次扣次。
- 联网奖励需能关联到玩家与唯一奖励事件；网络超时后查结果或重试时不能重复加次数。
- 联网同步合并“扣除/奖励事件”并返回修订后的状态，不能直接用客户端余额覆盖服务端或简单取较大值。并发、失败重试与事务策略待设计。
- 初版建议优先保证正常用户不丢次数、不开双重扣款；本地存档和设备时间可被修改，离线开局意味着无法承诺严格实时防作弊。服务端签发离线额度也不能撤销已在离线发生的游玩。
- 已有次数可离线使用，不等于已确认离线自动恢复；是否允许、计时依据和回拨处理仍待决定。
- 若要求同一玩家多设备离线游玩，必须明确设备额度分配与冲突策略，不能让两台设备同时各消费完整的同一份云余额。首版是否只支持一个活跃设备也待确认。
- 云备份需要可恢复的身份及冲突处理；开发仓库的 Git 同步不等于玩家存档同步。

## 实现前需补全

- 存档结构版本、升级迁移、损坏备份、持久化失败提示与重要事件可靠落盘。
- 开局扣次与异常退出的返还边界，进程被杀后的续局规则。
- 次数恢复是否允许离线，次数到上限/广告补充时的计时与溢出规则。
- 匿名身份、换机/重装恢复及多设备策略。
- 广告平台选择、奖励校验回调、延迟/中断/重试与补发；分享核验不能套用广告的服务端回调假设。

## 官方资料核对

- [Cocos Creator 3.8：存储和读取用户数据](https://docs.cocos.com/creator/3.8/manual/zh/advanced-topics/data-storage.html)：提供 `sys.localStorage` 与 JSON 序列化存取。用于小型原型存档是本轮建议；该接口不自动提供云同步或可信防作弊。
- [AdMob iOS：服务端验证](https://developers.google.com/admob/ios/ssv)：说明服务端奖励回调、签名校验和唯一 `transaction_id`。本轮据此建议服务端验证和交易去重；并未选择 AdMob，也不推断所有渠道都提供相同能力。
