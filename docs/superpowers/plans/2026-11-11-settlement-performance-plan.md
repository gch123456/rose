# 结算演出实施计划（阶段 C 遗留表现项）

日期：2026-11-11。依据：主题设计 `superpowers/specs/2026-11-11-duck-escape-theme-design.md`（失败变鸭货、约 1–2 秒可跳过、保留真实死因）与 V0.2 评审稿「结算表现」；上一阶段：`2026-11-11-stage-d-characters-save-plan.md`。

## 目标

把 `GoDuck.ts` 的占位结算面板换成两段 2 秒内自动完成、点按/按键可跳过的演出：

1. **失败「被做成鸭货」**：鸭子滑入包装盒 → 盒盖合上 → 贴上按真实死因映射的菜名标签。
2. **胜利「突围」**：出口门洞发光打开 → 主角鸭跑出 → 下一只待解锁职业鸭弹出解救（链上无待解锁则「三只职业鸭都自由了！」），少量彩点庆祝。

演出结束（或跳过）后仍显示现有结算面板（死因/解锁提示/统计），信息不丢失。

## 规则约束（可测部分）

- 菜名映射按死因确定性给出：手套→手撕鸭、夹子→脆皮鸭卷、锅盖→铁板鸭、Boss冲撞→包装鸭脖、Boss弹丸→爆浆鸭丸、超时→封坛老鸭、未知→卤鸭拼盘。
- 解救目标 = 解锁链（warrior→mage）上第一个未解锁职业；全解锁返回 null。该纯函数放 `SaveData.ts` 用 Node 测试（`nextUnlockTarget`）。
- 演出时长 2 秒上限，任意点按/按键立即跳过；跳过与自动结束都进入同一面板，不重复发奖（沿用 recordResult 幂等）。

## 实现要点

- `GoDuck.ts`：`settleFor` 状态（-1 未结算 / 0..2 演出中 / ≥2 面板），`update()` 每帧推进，`won/lost` 以外阶段复位；`drawSettlement()` 用程序图形绘制（不新增素材）；跳过挂 `touchStart`/`keyDown`；菜名/解救文案复用 `banner` 与 `progress` 标签。
- `SaveData.ts`：新增 `nextUnlockTarget(save)`。
- EscapeGame 规则层不动。

## 不做

- 不生成新美术素材（演出全程序图形）；不做失败动画多结局分支；不改胜负判定。

## 验证

- TDD：`nextUnlockTarget` 先红后绿；`npm test` 全过。
- Creator TS 诊断 0 错误；预览 bundle 编译确认。
- 真人验证留待用户实玩（演出节奏/菜名幽默感主观）。
