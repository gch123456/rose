# 私有关卡制作工具

2026-11-16。用户确认：只有作者上传图片；暂无Meshy账号/API，先做好工具，再配置服务。

## 目标与范围

独立于玩家界面的本机网页制作工具。上传参考图、保存工程、导入完整3D模型、控制积木数量/颜色数/队列难度、旋转预览、试玩并导出关卡。当前先支持本地GLB导入以及内置实体样例。图片上传本身只保存参考，不伪称完成3D重建。未来接Meshy，凭据仅本机服务端环境变量，现阶段不联网生成、不收费、不新增外部账户要求。

## 路线与已确认

- 完整模型→体素积木→规则关卡：推荐路线；用户确认先做作者工具、暂无服务权限，先完成不依赖服务的部分。
- 图片轮廓加厚：便宜但背面简单；不作为完整3D方案，不暗中替代。
- 玩家上传：明确不做。

## 制作界面

桌面优先，窄屏可滚动。左侧参考图/模型/参数；中间真3D完整模型和分块结果切换/旋转；右侧实际块数/颜色账本/校验结果与导出、试玩。图片生成按钮明确未配置并不可用。参考图本机读取，原文件不上传。允许PNG/JPEG/WebP，拒绝超限/不合法文件；模型先支持自包含GLB，不加载外部URI或在线贴图，不执行脚本。超大模型/积木生成前拒绝并保持上一有效结果，释放旧geometry/material/texture/objectURL，错误能恢复。

提供清楚标注的内置立体样例，方便尚无生成服务时验证完整流程。不能将样例或图片浮雕包装成用户上传图片的AI生成结果。

## 分块与外观

以完整封闭实体为输入，归一化包围盒，按可调网格采样内部/表面体素；颜色从模型材质或预设调色板归并，保留有效实体轮廓。输入开放/薄片可能失败，报告不适合体素化，不静默变成实心长方体。第一版使用封闭圆角块，实际显示/遮挡一致，避免球间缝隙和中空实体难判断。

数量默认400，可试200/400/600，上限800；用户选择是目标数量，实际由网格采样得到，必须显示实际值，不能靠随机删块凑数破坏轮廓。第一版不做任意平滑模型精确曲面切割。先做可重复、受限的生成算法，颜色2–6并配符号，运行时不得改变颜色。

## 弹药守恒与可解性

每发命中只清一个同色积木；标准关卡禁用免费跨色连锁，原有核心可在新规则中仅作为视觉/音效标记，不能额外清块。生成每色总弹量严格等于该色积木数，无打空/重复预留/在途丢弹。所有旧10关同步迁移此规则并提高积木密度，旧10个图册ID不变。

供应按真实可剥离顺序构造参考通路，分配四条队列；难度由连续颜色批次长度和供应顺序/遮挡控制。生成不出四槽无奖励通路则不可导出，必须给出原因，不能只检验总量。试玩导入不写正常通关图册或解锁进度。密度增大单独控制局长和细节，不标为保证更难。

所有时刻应可检验：各色活块数=队列/槽/暂存剩余弹量+在途该色弹数。获胜后无多余弹；失败仍允许因装满不匹配颜色而发生，不能因缺配弹发生。复杂情况不宣称任意顺序都能通关。

## 文件与接续

版本化关卡JSON只包含ID/名称/细胞坐标与颜色/四列弹药/初始视角/参考解/配置和校验摘要；不能包含凭据、参考图片或可执行代码。读入做尺寸/类型/坐标唯一/ID/颜色/弹量/总量/可解性校验。工程单独保存参考图（有尺寸上限）和配置；完整GLB由作者保留/重新选择，首版不构建服务端资产库。玩家入口独立于工具，不添加创作按钮。浏览器本地文件选择/预览不意味着Cocos已完成运行时GLB导入。

## 验收

1. 三种形状、不同数量/颜色/难度生成，实际数量在目标合理区间，视觉保持轮廓。
2. 每关每色弹量匹配；多槽连点/旋转/暂停/续关期间守恒，不能点完供应后因配额不足剩块。
3. 十关和制作关卡均四槽参考路径真实通关；随机策略可能槽位失败，但不缺配额。
4. 上传图片显示参考；未配置AI入口诚实；本地GLB与示例能够分块/导出/导入试玩；坏输入不覆盖有效关卡。
5. 原有连续输入、上下观察/自动转、图册、模拟奖励回归；Cocos代码同步规则，Creator/微信/iPhone未验证明确记录。

## 交给实现者的选择

可按性能选择射线奇偶/扫描线填充等确定性体素算法、局部坐标归一化方式和采样分辨率搜索。不得宣称有限采样恢复原图不可见面。实现阶段根据实测限制模型三角面数、图片字节数、网格范围和计算时间；错误必须可见。
