# 鸭鸭救援营地：模型清晰度与界面讨论稿

2026-11-17（北京时间）。起点 main c117921。状态：设计候选，等待作者确认；本轮没有改游戏代码、关卡、奖励或后端。用户要求检查4500格仍不清晰的原因、考虑更多颜色，并围绕鸭子自救原创设计首页、每日入口弹层、图鉴及音乐/音效设置。对方游戏截图仅用于识别页面职能，不复制图像、素材、文案或界面组合。

## 已核实的事实

- 法师鸭4500格，27×29×23。采样器把原贴图以Lab最近色压成6种纯色；游戏main.js把同一逻辑色直接作为实例显示色，试玩数据校验最多6色。复杂衣纹、面部细节确实会在此过程中丢失。
- 当前导入模型的animalDetails直接返回空数组，内置模型的眼睛等细节没有补到上传法师鸭；只提高体素数量不能解决这一点。
- 导入数据上限6000格；采样脚本目标上限5000。超出需要明确扩容和性能验证，不能只改目标数。
- 完整体积4500→6000时，同形状平均每轴采样密度仅约增加10%；4500→9000约26%。这是立方根估算，实际栅格离散会偏离；不是实测画质或性能承诺。

## 建议的模型方向（未实施）

优先拆开逻辑色与显示色：继续6种弹药颜色，每种允许3–4档邻近明暗，约18–24种外观色。逻辑color决定命中、库存和配额；visualTint只参与绘制，不新增弹药或影响可解性。色族必须一眼可辨，不能把阴影调到邻近弹药色。版本化数据、合法色值校验、导入导出和图册缩略图需一起适配。

给法师鸭人工标定眼睛、鸭嘴、帽檐与法杖识别点。眼睛/小装饰依附所属可消除块，随块消失；不能在空中留下漂浮五官，也不能成为额外不可消除障碍。保留原始GLB，不覆盖历史采样。

先做同一角度、同一屏幕大小的4500格纯色/4500格细节版对照，再以约6000格看轮廓收益；不直接跳上万格。接近连续表面的细接缝、适度倒角和柔和照明作为候选，需防止表面粘连难以判断可清块。维持恒定快消与拖动释放一秒恢复自动转。

## 界面概念

概念板：[三页界面草图](../art-samples/ui/2026-11-17-duck-rescue-camp-concept.png)。使用内置图像生成功能绘制，非运行截图、非已接入素材；纸张纹理与场景细节是美术方向，不代表移动端必须实时3D渲染。正式首页可使用预渲染背景加少量角色动画。

推荐暖奶油纸、深松绿、杏橙按钮的救援营地。其他可行方向是偏荒诞紧张的后厨逃生站；当前推荐营地，是为了让每日回来与收集到鸭子的情绪更轻松。主题仍是逃离变鸭货，并非恢复保卫家园。

- 首页：左上设置；右上为微信胶囊预留安全区。中间一只待救职业鸭和当前任务，唯一主按钮“出发救鸭”，有实际存档时才显示“继续上次救援”。小信封打开补给；底部“营地 / 救援手册”。暂不加排行榜或多排活动入口。
- 每日补给：营地上当日首次进入展示一次可直接关闭的信封底部面板；标题“每日补给”，候选奖励“随机重排×1”，按钮“收下补给”。关闭后仍可点信封领取；领取后改成已领取。不把转发当免费补给的必经条件。现有重排功能不等于已有每日库存、时间校验或真实奖励接入。
- 救援手册：全屏上下滚动，按救援路线分章节，双列照片卡；已救鸭有“安全抵达”印章，可点看旋转模型，未救的用轮廓与真实解锁条件。进度按实际可发布关卡计，不把概念图2/10写成真实账号数据，不展示虚构几千关。沿用当前访客/账号图册归属，不凭概念图增加解锁记录。
- 设置：轻量面板，音乐、音效两个独立开关，关闭设置后保留偏好；音量入口不挤占首页。音乐素材与播放尚需后续实现，不把现有音效开关冒充两路音频。

概念板中的“侦察鸭”、章节名、“继续上次救援”及每日道具库存均为候选，不表示现有角色/关卡/断点存档已支持。移动端需复核文字字号、底部安全区、触控尺寸及微信胶囊避让。
