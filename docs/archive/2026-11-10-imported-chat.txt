可以。这个云端环境能用来写项目、运行命令，再通过 Git 提交并推送到 GitHub、GitLab 等远程仓库。

一般工作流程：

克隆已有仓库，或创建新项目。
在云端编辑代码，通过终端安装依赖、运行项目、测试。
用 git add、`git commit`、`git push` 保存到远程仓库。推送需要配置相应账号的访问权限。
你说的“各个终端”有两种情况：

同一个云端环境里的多个终端：通常共享项目文件，可以一个运行服务、一个执行测试、另一个操作 Git。
本地电脑或其他云端环境的终端：通过同一个 Git 仓库 push / pull 同步；文件不会自动实时同步。
建议把代码及时推送到远程仓库，云端环境是否长期保留要看平台设置。

我觉得方向可行，“鸡鸭鹅保卫家园”很适合做成轻松、有反差感的生存小游戏，Cocos Creator + TypeScript 也适合这个项目。 最需要打磨的是三分钟内的成长节奏，以及“保卫家园”怎么真正体现在玩法中。

你的核心循环已经完整：走位 → 自动攻击 → 捡食物升级 → 三选一搭配 → 进化 → 打 Boss。我的建议是：

让动物有鲜明的玩法区别。 鸡偏啄击和攻速，鸭偏水波和减速，鹅偏叫声击退与范围攻击。初始武器和天赋不同，就能形成角色辨识度。
三分钟一局需要压缩成长。 传统的 6 武器、6 被动，加上多级升级和进化，可能还没成型就结束了。原型建议先做 3 武器、3 被动，保证玩家一局至少体验一次进化，再决定是否扩成 6+6。
怪物密度可以看起来爆炸，但不要无限指数增长。 用分段刷怪、数量上限、怪物组合制造压力，兼顾手机性能。升级弹窗期间暂停战斗和计时。
Boss 要考验走位。 冲撞、扇形扑击、地面预警，都适合没有攻击键的操作方式。三分钟结束后进入 Boss 阶段，并给 Boss 战单独的时间预算。
宝箱随机奖励，进化条件尽量明确。 例如“啄击满级 + 辣椒 → 烈焰啄击”，满足后宝箱优先给进化，让玩家有目标地选装备。
武器槽满后，我建议默认只提供已有项升级；如果允许替换，要明确旧装备等级如何处理，避免选择突然变得复杂。
