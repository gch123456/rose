# 结算演出实施记录：鸭货包装与突围解救

日期：2026-11-11（北京时间）。执行：WorkBuddy Agent（Superpowers 流程）。上一阶段：`2026-11-11-stage-d-characters-save-session.md`。

## 决定

- A/B/C/D 玩法主线全部完成后，用户在四个候选方向（结算演出/开局次数/职业素材/先试玩调参）中选择了**结算演出**：把占位结算面板换成 1–2 秒可跳过的演出，符合主题设计「失败被做成鸭货、保留真实死因」与 V0.2 评审稿的结算表现条目；该项原列在阶段 C 清单的遗留表现项。

## 实现

- `SaveData.ts` 新增纯函数 `nextUnlockTarget(save)`：解锁链（warrior→mage）上第一个未解锁职业，全解锁返回 null——胜利演出的解救目标与解锁逻辑共用同一数据源。
- `GoDuck.ts` 结算状态机：`settleFor`（-1 未结算 / 0..2 演出中 / ≥2 面板）；`won/lost` 进入演出，每帧推进，2 秒自动结束；任意点按或按键置 2 跳过；演出期间结算面板延迟构建，跳过与自动结束进入同一面板，`recordResult` 幂等保证不重复发奖。
- **失败演出「被做成鸭货」**：鸭子滑入礼盒 → 盒盖合上 → 菜名标签弹出。菜名按真实死因确定性映射：手套→手撕鸭、夹子→脆皮鸭卷、锅盖→铁板鸭、Boss冲撞→包装鸭脖、Boss弹丸→爆浆鸭丸、超时「出口被封锁」→封坛老鸭、未知→卤鸭拼盘；横幅显示「被做成XX…」。
- **胜利演出「突围」**：顶部出口门洞发光展开 → 主角鸭跑出 → 解救目标职业鸭弹跳登场 + 彩点庆祝；横幅显示「解救了战士鸭/法师鸭！」或全解锁时「三只职业鸭都自由了！」。
- 全部为程序图形绘制，无新增素材；EscapeGame 规则层零改动。
