## 工程优化候选（2026-11-14 调研，未实施）

用户指示「找 cocos 官方的素材库，找到有没有可以优化的地方」。核查结论：**收益最大的不是素材，而是引擎/渲染层**。以下均为候选，本轮只登记、未改代码、未重建产物；完整证据、授权边界与未验证项见 [本轮归档](archive/2026-11-14-cocos-official-assets-review.md)。

- [ ] **P0-1 功能裁剪**：纯 2D 项目却把 3D 物理 Bullet（458K wasm）与 Spine（200K wasm）等约 **700K 未压缩体积**打进微信包（主包 5.0M 的约 14%）。官方[物理选项文档](https://docs.cocos.com/creator/3.0/manual/zh/physics/physics-item.html)说明不用物理时可取消勾选以缩包；`settings/v2/packages/engine.json` 目前只有 `__version__`，即走默认全开。改法：编辑器「项目 → 项目设置 → 功能裁剪」取消 3D 物理 / 3D / Spine，重建后对比体积并双模式回归。
- [ ] **P0-2 动态合图**：官方[动态合图文档](https://docs.cocos.com/creator/3.8/manual/zh/advanced-topics/dynamic-atlas.html)注明小游戏与原生平台**默认禁用**；项目未写 `macro.CLEANUP_IMAGE_CACHE` / `DynamicAtlasManager`，59 张独立 `Texture2D` 是 DrawCall 主因。官方代码须写在脚本**最外层**（不能放 `onLoad`/`start`），贴图 < 512 才参与（现有 48px 精灵全满足）。代价是额外内存，须真机验证。
- [ ] **P0-3 Label CacheMode**：约 30 个 `Label` 均未设置 `cacheMode`（默认 NONE，一个 Label 一个 DrawCall）。固定文本用 `BITMAP`、频繁变动的 HUD / 伤害数字用 `CHAR`；按 3.8.8 API 实测。
- [ ] **P0-4 图集化**：`duck/manifest` 逐张 `resources.load` 56 帧 → 改 `SpriteAtlas` / Auto Atlas，一次加载一张纹理；另按官方建议把不需动态加载的图移出 `resources/` 以免撑大 settings 映射。
- [ ] **P0-5 先量基线**：`GoDuck.ts` 已 `import { profiler }`，先在真机/微信开发者工具采 190 敌人时的 DrawCall 与帧率，再决定上面几项的取舍。
- [ ] **P1 候选**：官方技术方案里的 `Creator3.6.0_2D_QuadtreeCollision`（190 敌人 × 弹幕的碰撞空间划分，需移植到纯规则层）、`Creator3.6.0_2D_Light`（若采纳沉没地牢的发光水母/水下光柱）、`Creator3.6.0_GameTimeScale`（tween 变速，与已登记的 pixelfx `act` / animista 缓动同一议题）；`Graphics` 无法合批且会打断合批，8 处每帧 `clear()` 重绘可改成分层按需重绘；音频从 `AudioContext` 换 `AudioSource` ＋预加载；微信[初始场景分包 / 分离引擎 / 纹理压缩](https://docs.cocos.com/creator/3.7/manual/zh/editor/publish/publish-wechatgame.html)（像素风慎用有损压缩）。
- [ ] **不建议现阶段做**：Store 付费「98K 多纹理合批 3.x」（第三方、需改材质）、Spine / DragonBones、3D 光照与后处理、VideoTexture（官方明确不支持微信小游戏）、Marionette、TiledMap 寻路。
- 触发条件：用户明确要求做性能优化或真机帧率不达标时，从 P0-1 与 P0-5 开始，落地属渲染/构建层改动，需重跑 `npm test`、重建微信竖屏产物并单独归档。

## 备选方案（未采纳 · 待触发评估）

### pixelfx · 代码绘制的像素特效库（2026-11-13 记录，本轮明确不实施）

- 来源：`patch-gg/pixelfx`，2026-10-30 开源，MIT（代码与特效可商用；`gallery/fonts` 的 Patch Pixel 字体不在授权内，部分代码改编自 Hugo Duprez / Hollow Crown 的 MIT 项目，须保留 NOTICE）。
- 内容：244 个用 JavaScript 写出来的像素特效，21 类（fire / explosions / lightning / melee / impacts / projectiles / ui / pickups …）。渲染模型为 `color` + 加法 `light` 双缓冲、全种子化随机、局部坐标系、传 `palette` 换色；核心 API `createFrame / createFx / composite`，无第三方依赖。
- 额外价值：61 个带角色特效与 12 套招式带 `act` 时序数据（`hits: [{ t, stop, shake, push }]`，命中冻结 0.14 秒、起手/后仰/收招），是「打击重量感」的关键，而非更多粒子。
- 接入约束：Cocos Creator 3.8.8 的微信小游戏运行时**没有 DOM `ImageData` / `putImageData`**，pixelfx 的 JS 运行时不能 import 后直接跑；网页预览页（Canvas 2D）可以，但会与微信产物分叉，不作为主方案。
- 若未来启用，推荐顺序：① 先把 `act` 的 hit-stop / windup 时序作为纯数据搬进 `SurvivorGame`（零素材、零包体）；② 用 `node tools/render.mjs <id> --sheet` 把十几个关键特效离线烘焙成透明 PNG + Aseprite JSON，放进 `assets/resources` 由 `Sprite` 播帧动画。不推荐把 `composite` 输出每帧上传 `Texture2D`（微信小游戏纹理上传开销大，190 敌人同屏时帧率风险高）。
- 触发条件：真机帧率达标后、且用户明确要求提升打击感或替换手绘特效时再评审；**本轮只记录，不引入依赖、不改动渲染层**。

### pixel-search · 像素精灵图语义检索（用户确认「素材图对我有帮助」）

- 用户指示原话：「pixel-search的素材图对我有帮助，请记录一下」。核查后对应 Hugging Face Space [`cfahlgren1/pixel-search`](https://huggingface.co/spaces/cfahlgren1/pixel-search)（Pixel Search，作者 `cfahlgren1`，运行中）及其底层数据集 [`Angais/pixel-art-atlas-1.4m`](https://huggingface.co/datasets/Angais/pixel-art-atlas-1.4m)。同名的 npm 包（图像匹配 CLI）与安卓 App（搜索工具）与素材无关，不是本条所指。
- 数据集：`Pixel Art Atlas · 1.4M Synthetic Sprites`，**1,409,404 张 16×16 RGBA 透明底独立精灵图**（不是 sprite sheet）、6,194 个 subject、每条含 `image / caption / subject / row_id`，Parquet 共约 694MB；由 Krea 2 Turbo ＋ pixel art LoRA 文本生成，全部是 AI 合成输出。
- 检索能力：浏览器内**文本语义检索**，每敲一个字符实时重排；离线用五个开源 encoder 把约 35k 词与 6,194 主题压成 96 维 int8 向量，浏览器 Web Worker 做点积打分并按 caption 属性重排，WebGL2 / OffscreenCanvas 绘制。README **未说明支持以图搜图，也未提供结果下载或导出入口** —— 它是浏览/找参考图的工具，不是一键素材包。
- 对本项目可能补的缺口：现有素材仅 59 张（56 张八方向鸭＋3 张敌人）；割草模式只有 3 种敌人贴图复用，待救小鸭、魂珠、特效均为手绘；网页试玩页完全无贴图、与微信端观感分叉。可用于找新敌人/精英/Boss 造型、道具与魂珠图标、UI 像素元件、场景 tile，以及「找回像素感」的参考图。16×16 需整数倍放大并沿用 `NEAREST` 滤镜，才能和现有 48px 精灵匹配。
- **授权边界（接入前必查）**：数据集元数据 `license: cc0-1.0`，但权利声明限定在「Angais 可放弃的权利范围内」，不授予第三方材料、商标或 Krea 模型权利，且明确**不覆盖 Krea 2 Community License §2.3 商用条款与 Krea Acceptable Use Policy**；Krea 依 §5.3 不对生成输出主张所有权；该数据集非 Krea 官方发布；无强制署名（捐赠为可选）。因此不能把 CC0 字段读作无条件商用保证 —— 打进微信小游戏包前须逐项核对 Krea 条款/AUP 并留存来源记录。caption 只是生成提示的近似标签、图文一致性未系统审核，必须目视挑图。
- 状态：**本轮只登记**：未下载素材、未引入图片、未改渲染层、未增加包体、未动玩法与测试。
