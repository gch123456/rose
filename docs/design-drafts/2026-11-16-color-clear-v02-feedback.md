# 转转积木第二轮反馈与可行性

日期：2026-11-16。用户在试玩后提出以下需求，随后确认采用“保留余弹、暂存胶囊并继续本局”。已按本稿建议实现浏览器原型；下文保留讨论时的取舍，当前事实以[实施记录](../archive/2026-11-16-color-clear-v02-implementation-session.md)为准。

## 用户明确提出

1. 去掉空发射台加号。
2. 加强从发射台到3D模型的发射动效。
3. 进度条与剩余块数做成可配置，去掉多余说明字体；可增加背景。
4. 模型应依据实体形状呈现真实立体感，如动物；构成块不必全是立方体，可用圆、半圆、梯形等。
5. 基础4槽，可扩成5槽、6槽，考虑分享或广告解锁。
6. 满槽且不再消除时失败；广告后清空发射台，保留本局继续，不重新开局。

## 可行性与建议（提案，尚待评审）

- 界面调整较轻：移除空槽加号；说明文字默认隐藏，保留弹量和必要操作；进度条与剩余块数独立开关、默认隐藏。配置与实际游玩存档区分，方便不同版本试验。
- 现有弹丸在模型canvas内生成，较小且飞行约0.12秒；规则在发射事件时已清块。需要改为从实际槽位位置发出，增加炮口闪光/回弹、弹道和命中音，命中后清除。还须处理飞行中目标预留、旋转、暂停与胜负结算，避免两发重复打同一块或提前判死局。
- 背景可从低对比玩具工坊/展示台开始，模型与弹丸保持最高识别度；不把装饰背景变成需要观察的额外内容。
- 模型两条路线：圆润小块组成可辨识的立体动物，逐步加入边缘半球/楔块（推荐首轮）；或将完整高精模型切成任意曲面碎片（建模与运行成本更高）。当前规则用规则网格上的完整立方体遮挡，直接换成球形贴图/网格会产生视觉与命中不一致；必须同步改遮挡几何、邻接连锁与关卡解法验证。不是只换模型文件。
- 扩槽建议基础4槽＋两个独立锁定槽，第5、第6分别解锁，默认仅本局有效。永久解锁属于另一种难度设计，未视为用户确认。已入槽数字改为动态容量；满槽条件必须使用当前容量。
- 失败建议维持“满槽＋全部允许旋转角度都无可打目标”，正在发射、子弹在途、连锁未结算或转动即可恢复时不判负。不能简单采用当前视角短时间无击杀。
- 续关冻结并保留已消除模型、供应队列、余弹、解锁槽、旋转状态与关卡编号。清空仅发射台；原胶囊移入可重新取用的临时暂存区，保存剩余弹数，不堵住原供应前排。需要单独定义暂存区入口和取回交互，避免只把胶囊放回前排造成同一死局。每关先限1次续关为建议，尚待确认。
- 广告成功才发奖；加载失败或中途退出保留失败现场，重复回调不重复扩槽/续关；关卡重开或切换后旧广告回调不得改变新局。浏览器只能做明确标注的模拟入口，不能假装已有微信真实广告。
- 分享解锁涉及平台诱导分享与奖励规则，不能将其当已验证可上线能力。建议先做普通自愿分享与广告解锁分开；正式接入前核对小游戏专项规则及账号广告条件。

## 待用户决定的关键点

“清空发射台”后的剩余胶囊是否允许保留在暂存区并再取用？推荐保留，否则原关卡按有限弹量设计，直接删掉胶囊可能导致无法通关。失败、扩槽时效和续关次数按上述建议先讨论，不把建议记成用户已批准。

## 验证计划与现状

代码核查确认当前固定4槽、空位加号、短弹丸与发射即消除；当前支持立方体网格，不支持任意曲面分块。上述更改尚未实施；旧测试结果不算本轮功能验证。
