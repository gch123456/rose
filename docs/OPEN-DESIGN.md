# 尚需补全的设计与本轮建议

更新日期：2026-11-11（北京时间）。这是已确认方向与待定参数清单，**不是完整获批的实施设计**。
当前代码行为以 [DESIGN.md](DESIGN.md) 和脚本为准；此处数值为试玩起点，不直接替换实现。

## 已确认的方向

- 单指移动、自动攻击，玩家专注自身走位与割草，家园仅为背景。
- 自动小成长＋少量场内走位二选一，更早出现成片击杀，保持通关挑战。
- 首套彩色像素音画按已记录范围推进，PixelLab 另台电脑接入，本机不继续安装。
- 用户明确“血条”指局外有限开局次数，用完后看广告或分享补次数；与局内角色生命分开。具体参数及分享奖励的平台可用性待定。
- 已有次数可离线开局，广告补次数需要联网；离线自然恢复未定。持久化清单与后端建议见 [PERSISTENCE-NOTES.md](PERSISTENCE-NOTES.md)，尚未实现。

## 优先补全的六组规则

| 项目 | 需要明确 |
| --- | --- |
| 成长 | 每级自动强化什么；重要二选一出现几次、何时出现、如何摆放；不选或已经满槽时如何处理 |
| 生命与失败 | 生命显示、碰撞/精英/Boss 伤害、受伤保护、回血来源、死亡和复活后的状态 |
| 敌人与节奏 | 普通怪承担成片击杀，高威胁敌人提供可读压力；出生方向、逃生路线和 Boss 预警 |
| 关卡 | 原型/首发数量、每关新增体验、解锁条件、独立开局还是连续章节 |
| 重玩与保存 | 局内能力何时重置；关卡/动物解锁是否保存；切后台、退出与恢复规则 |
| 商业化与发行 | 是否广告、可选复活次数、无广告库存/中断时流程、分享用途及目标平台适配 |

横竖屏、角色显示尺寸和触控区域也需在品质样段前明确，以便确定界面与素材规格。

## “血条”含义已澄清

用户已回答：“开局次数有限，用完后看广告或分享补次数”。术语分开：

1. **局内生命**：角色受伤扣除，本局归零后死亡。
2. **局外次数/体力**：决定还能开几局，与本局受伤无关。

本次确认的是第二种；并未确认局内五格生命或死亡广告复活。此前无限免费重开的建议已被此方向取代，保留在历史会话中，不再作为当前产品方向。

## 开局次数建议（方向确认，参数待定）

- 测试起点：上限 5 次，正式开局扣 1 次，死亡不再额外扣除；每 10 分钟自然恢复 1 次，达到上限停止恢复。
- 自愿看完一次激励广告补 2 次；分享补次数是用户希望的路径，具体奖励量、次数上限、有效完成判定需按首发平台核对后决定，不能先承诺可上线。
- 自然恢复使无广告库存、拒绝广告或不分享时仍能再次游玩；广告取消、中断、无库存时不扣现有次数，奖励以有效完成结果为准。
- 建议教学不消耗次数，切后台优先恢复原局；异常退出的扣除/返还、离线恢复和存档防重复发奖需另行设计。
- 补次数仅在局外发生，不在战斗中弹广告或分享提示。第一版建议先只做补开局次数，不叠加死亡广告复活，避免同时测试两套广告规则。
- 上述数字、自然恢复与异常处理均为建议，尚未获用户确认或实现。原型开发测试可保留不限次数的调试入口，不能据此把正式方向改回无限重开。
- 验证重点：玩家是否想继续却被次数阻断、是否愿意等待/看广告、广告退出与次日回访；不把“次数耗尽”直接当作留存成功。

## 局内生命建议（待确认）

- 只有一份角色生命，可显示为 **5 颗心/生命格**；并非五条独立命。
- 测试起点：普通碰撞扣 1 格，明确预警的重攻击扣 2 格，受伤后约 1 秒保护，防止被同一群怪瞬间连续结算。
- 少量恢复食物可补 1 格，不超过上限；掉落规则还需验证。
- 归零后本局失败，能否再开局取决于局外次数；具体生命格与恢复规则仍需试玩确认。
- 当前不将广告复活视为已确认需求；不通过人为制造不可躲的伤害促进广告。

当前代码仍是 100 生命、普通伤害 8、Boss 22、保护 0.65 秒，无广告/次数系统；未按上述建议改造。

## 关卡范围建议（待确认）

目前只有一张原型地图。先打磨 **1 关**；验证通过后，以 **3 关**作为首个正式版本候选范围。
每关是一局独立挑战，先沿用 180 秒怪潮后进入 Boss 的结构；关后进入选关/结算，新开局重新成长，不把三关拼成一次长局。

| 候选关卡 | 主要体验变化 |
| --- | --- |
| 菜园 | 基础虫群、拾取与第一次构筑，学习保留逃生方向 |
| 池塘边 | 增加高速敌人与交替来袭方向，避免一直沿同一圈跑 |
| 谷仓外 | 混合敌人与有预警的范围威胁，检验走位和能力搭配 |

每关需有机制变化，不仅改变背景、血量和数量。Boss 可先用现有素材验证不同攻击模式，再决定正式美术数量。
通关解锁下一关；已解锁关卡可自由重玩。首发后可基于原地图增加难度变体，避免提前承诺大量关卡。
解锁、存档、Boss 与结算奖励均需进一步设计，不因本表自动定稿。
